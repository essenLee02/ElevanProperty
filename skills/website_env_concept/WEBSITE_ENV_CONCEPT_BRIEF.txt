1. OVERVIEW
------------------------------------------------------------------------------
Elevan Property = platform properti full-stack untuk pasar Indonesia:
  - WEBSITE (Vue 3) : landing, About, Contact, Rumah123 search, Auth, Profile,
                      Facility master, + floating AI chatbot.
  - BACKEND (Node/Express) : REST API, auth JWT, AI orchestration, integrasi
                      WhatsApp multi-platform & multi-agent, data properti.
  - AI ASSISTANT    : mengkualifikasi kebutuhan customer (sewa/beli, tipe,
                      lokasi, budget, fasilitas, dll) lalu menghasilkan SUMMARY
                      rapi untuk customer & agent. Rantai: ChatGPT → Claude →
                      Private Agent (deterministik, tanpa token).
  - WHITE-LABEL     : nama agent & perusahaan SELALU dinamis
                      (${agentName} dari DB/session, ${appName} dari APP_NAME).

Satu pesan masuk (web atau WhatsApp) → gate kata-kunci properti → ekstraksi
filter + state kualifikasi → balasan AI (pertanyaan berikutnya / summary) →
simpan ke DB → opsi log terminal.

------------------------------------------------------------------------------
2. TUJUAN (GOALS)
------------------------------------------------------------------------------
- Satu pengalaman chatbot konsisten di web DAN WhatsApp (pipeline AI sama).
- Kualifikasi lead tanpa pertanyaan berulang & tanpa halusinasi data.
- Multi-agent: tiap agent punya nomor & token sendiri (Fonnte/WATI/ChakraHQ).
- Website rapi, modular, komponen reusable (table/modal/pagination via fungsi).
- White-label penuh; rahasia .env tidak pernah di-echo/commit.
- Fallback terjamin: Private Agent selalu bisa menjawab walau LLM mati/kuota.

6. SKILLS (kemampuan & aturan respons AI)
------------------------------------------------------------------------------
- Skill = file .md dimuat runtime oleh skillPromptService (tanpa restart):
    chat_gpt_responds/  → untuk ChatGPT     claude_responds/ → untuk Claude
    KEDUANYA WAJIB SINKRON (hanya frontmatter provider yang beda).
- Aturan NON-NEGOTIABLE:
    • Satu pesan = satu pertanyaan.
    • Budget via DUA opsi harga kontras (jangan tanya nominal langsung).
    • Kamar di-infer dari "tinggal bersama siapa".
    • Decision maker via logistik viewing (bukan "siapa yang putuskan").
    • Hanya pakai field ✅ di QUALIFICATION STATE; jangan mengarang.
    • "beli"→sale; bahasa balasan mengikuti bahasa customer.
    • Tanda tangan dinamis ${agentName}/${appName}.
- Kualifikasi Q1–Q12 (+ Q_FAC fasilitas WAJIB untuk SEWA; BELI: Q_KPR/Q_COND;
  Q14 spesifik per-tipe). 12 tipe properti × sewa/beli = 24 kombinasi.
- HOUSE v2 PILOT (building_type=house): asisten tak bernama, tambah QM (motivasi)
  + QF (kesiapan finansial), akhiri SUMMARY ✓/✗ + handoff + [BRIEF_READY] internal.
- Parser deterministik (server, bukan tebakan LLM):
    customerDateParser → "DD Bulan YYYY"; customerMoneyParser → range IDR;
    detectFacilities → label fasilitas (word-boundary).

7. WORKFLOW (alur 1 pesan + cara kerja pengembangan)
------------------------------------------------------------------------------
ALUR PESAN MASUK:
1) Webhook platform (Fonnte/WATI/TimelinesAI/ChakraHQ) atau chatbot web masuk.
2) GATE propertyKeywordFilter: hasPropertyKeyword OR isPropertyContextContinuation
   → jika bukan properti & bukan lanjutan → di-skip (tidak disimpan, tidak dibalas).
3) extractPropertyFilters(message, history) — gabung pesan + akumulasi 24 pesan.
4) whatsappAIService.generateWhatsAppAIReply:
   - Pre-Qualification Gate (buildQualifyReply): pastikan 4 info inti.
   - extractQualificationState (Phase 0 batas sesi; 1 scan konten; 2 pairing AI↔cust;
     3A summary-shown; 3B ganti tipe → reset Q2–Q12) → buildQualificationStateBlock.
   - Mode OFF: tanya field ❓ terkecil; semua wajib ✅ → SUMMARY BRIEF.
     Mode ON: tampilkan katalog setelah 4 info inti.
   - Provider: AI_PRIMARY_PROVIDER (chatgpt/claude) ATAU private (deterministik).
5) Simpan balasan ke DB; kirim balik via token milik agent; log terminal opsional.

CARA KERJA PENGEMBANGAN:
- Ubah perilaku respons → edit doc skill di KEDUA folder lalu pastikan SINKRON.
- Ubah logika deterministik → edit services/controllers + tambah/update test;
  jalankan `node backend/tests/<nama>.test.js` sampai semua hijau.
- Jangan hardcode nama agent/perusahaan; jangan echo/commit rahasia .env.
- Frontend: vendor & Function_Path dimuat sekali di App.vue; list view baru cukup
  duplikat FacilityListView dan ganti TABLE_HEADERS/CHUNKS/ACTION_* + API.

9. SOLUSI (pola solusi yang dipakai)
------------------------------------------------------------------------------
- Pipeline AI TUNGGAL (whatsappAIService) dipakai semua channel → konsisten.
- Normalisasi DETERMINISTIK (tanggal/uang) di server → LLM hanya menyalin.
- QUALIFICATION STATE sebagai satu-satunya sumber kebenaran (✅/❓).
- Phase 0 active-session boundary → pencarian lama tidak mencemari sesi baru.
- Gate kata-kunci + continuation → jawaban pendek/preferensi tetap lolos,
  obrolan harian/off-topic (mati listrik, kuliner) ditolak.
- Fallback berlapis → Private Agent menjamin balasan walau LLM gagal/kuota.
- White-label via ${agentName}/${appName}; rahasia hanya di .env.
- Frontend lean: vendor + helper sekali muat (App.vue); tabel/pagination via fungsi.

12. TROUBLESHOOT SUMMARY (gejala → akar → solusi)
------------------------------------------------------------------------------
- AI balas 502                  : OpenAI kuota + Claude key placeholder → isi
                                  ANTHROPIC_API_KEY atau set AI_PRIMARY_PROVIDER=private.
- Pesan WA tak tertangkap        : webhook platform tidak menunjuk backend (ngrok URL
  di terminal                     berubah / dashboard salah) → update URL webhook.
- "saya beli"/jawaban pendek     : controller belum import isPropertyContextContinuation
  tidak dibalas                   + getConversationHistory → pastikan keduanya dipakai.
- Jawaban preferensi/red-flag     : kena guard off-topic/kuliner/daily-life → pastikan
  ter-drop (sejuk, banjir, cafe)  isPreferenceAnswer/landmark/flood-avoidance dikenali.
- AI ulang pertanyaan (QM/Q-x)    : reset terlalu agresif / hasX tidak kenal jawaban →
  walau sudah dijawab             flag has* diturunkan dari activeHistory, jangan diwipe.
- Summary kehilangan info          : field tidak dirender di houseSummary → tambah baris
  customer (yoga/banjir/sejuk)    (Fasilitas/Preferensi/Hindari) + detector terkait.
- Furnitur tak terdeteksi/loop     : jawaban telanjang "semi/full/kosong" → hasFurnishing
                                  + #extractFurnishing pakai \b(semi|full|kosong)\b.
- Master fasilitas duplikat        : input sinonim (gym/gym club, cctv/kamera) → cek
                                  FACILITY_SYNONYM_GROUPS + normalisasi nama.
- Contact form gagal               : FONNTE_TOKEN invalid → cek .env / dashboard Fonnte.
- Google Sheets tak tersimpan      : sheet belum di-share ke service account email.
- Rumah123 kosong                  : kuota Apify habis → RUMAH123_DATA=OFF (JSON statis).
- Login 403                        : user status 2 (blocked)/3 (deleted) → cek tabel users.
- DB tidak sync                    : MySQL/MariaDB belum jalan → start XAMPP/MariaDB.
- Cek cepat sebelum deploy         : `node --check <file>` + jalankan 5 suite test.

Status endpoints (JSON): /api/chatbot/ai-provider-status, /skill-status,
/private-status; /api/contact/google-sheets-status, /ai-whatsapp-status;
