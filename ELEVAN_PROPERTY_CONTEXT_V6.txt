>> BACA INI DULU — TIGA HAL YANG PALING SERING MENYESATKAN <<

  1. CEK JALUR PRODUKSI SEBELUM MENDIAGNOSIS APA PUN.
     Ada DUA basis kode qualification yang MIRIP tapi TERPISAH:
       • services/aiPromptBuilderService.js   → jalur LLM (Claude/ChatGPT/…)
       • controllers/chatbotPrivateController.js → Private Agent (FALLBACK)
     `AI_PRIMARY_PROVIDER=chatgpt` berarti PRODUKSI memakai jalur LLM.
     Memperbaiki Private Agent tidak akan mengubah apa pun yang dilihat
     customer. Sudah dua kali diagnosis salah arah karena ini (M52, M54).
     Verifikasi: `grep AI_PRIMARY_PROVIDER backend/.env` + log runtime
     `[WhatsAppAI] Calling AI provider: { primaryProvider: … }`.

  2. STATE SELALU DARI HISTORY PENUH — JANGAN PERNAH DIPOTONG.
     `extractQualificationState()` dipanggil DI DALAM buildWhatsappReplyPrompt.
     Memotong `history` sebelum memanggil builder = memotong input state =
     seluruh field jadi null pada percakapan panjang = loop tanya-ulang tanpa
     akhir (M64, pengulangan M35). Pemotongan token HANYA boleh mengenai
     transkrip yang DITAMPILKAN (`AI_PROMPT_DISPLAY_TURNS`, default 20).

  3. MENAMBAH ATURAN PROMPT ADA HARGANYA.
     Prompt WhatsApp per pesan ±53–56K token, sedangkan limit TPM
     gpt-4o-mini = 60.000/menit. Tiap aturan baru memperburuk rasio
     sinyal:derau dan menurunkan kepatuhan model secara global (M62).
     Bila sebuah loop bertahan MESKIPUN DIREKTIF FINAL sudah benar →
     yang kurang adalah EKSTRAKTOR (kode), bukan aturan prompt.


>> PERUBAHAN BESAR SEJAK V5 (31 Jul → 3 Agu 2026) <<

  1. DIREKTIF FINAL — obat "lost in the middle" (M62)
     Diukur: prompt satu pesan ±53.000 token; QUALIFICATION STATE (kebenaran
     otoritatif) hanya ±450 token dan berada di posisi 8%, disusul ±49.000
     token prosa. Rasio 1:109. Model memperhatikan AWAL dan AKHIR jauh lebih
     kuat daripada tengah → gpt-4o-mini kehilangan jejak state, menanyakan
     ulang Q1 yang sudah ✅, bahkan menolak "Saya sewa apartemen" sebagai
     non-properti. Fix: `buildFinalDirective()` menempel ±235 token di
     POSISI 100% prompt — mengulang field ✅, satu pertanyaan berikutnya, dan
     tiga larangan keras. Sengaja SANGAT ringkas; memanjangkannya justru
     memperburuk masalah yang sama.

  2. REGRESI SENDIRI: PEMOTONGAN HISTORY MERUSAK STATE (M64)
     `generateChatGPTWhatsappReply` sempat memotong history ke 12 pesan
     sebagai mitigasi TPM, dengan komentar keliru "state sudah dihitung
     sebelumnya". Nyatanya belum. Pada percakapan 19 pesan: transaksi, tipe,
     kota, budget SEMUA null → AI melihat sesi kosong tiap giliran → customer
     menulis "Tolong hentikan pertanyaan yang berulang". Sudah dicabut;
     pemisahan state/tampilan kini dipaksakan di dalam builder.

  3. Q3 — MENERIMA/MENOLAK HARGA YANG DITAWARKAN (M63)
     Q3 tidak pernah ditanya langsung; AI menawarkan dua harga kontras.
     Customer punya TIGA cara sah menjawab, dulu hanya satu dikenali:
       (a) menyebut angka sendiri        → sudah jalan
       (b) MENERIMA: "sesuai", "sudah sesuai", "iya", "ok", "cocok"
           → budget = rentang yang DITAWARKAN (satuan periode ikut)
       (c) MENOLAK: "kemahalan", "terlalu mahal", "mau yang murah"
           → tier terjangkau
     Sekaligus memperbaiki inversi lama: kata "mahal" dipetakan ke tier
     EKSKLUSIF, sehingga customer yang protes kemahalan malah dinaikkan
     tiernya. Deteksi anchor kini menang karena punya konteks lebih.

  4. Q4 — "N TEMAN" ADALAH JAWABAN PENGHUNI (M65)
     "Bersama 2 teman kerja", "tinggal bersama 2 teman krj saya", "bertiga"
     semuanya null karena regex mewajibkan kata "orang". Q4 diulang tanpa
     henti. Kini `N teman/kawan/rekan` → N+1 orang (customer ikut dihitung,
     sesuai konvensi AI sendiri "Kak + 5 teman"), `bertiga/berempat` → sesuai
     angkanya, dan "sama teman kerja" tanpa jumlah tetap dihitung TERJAWAB.

  5. Q2 — KOTA DIBACA BALIK DARI PESAN AI (M66)
     Hanya pesan CUSTOMER yang dipindai untuk lokasi, sehingga Q2 bisa jatuh
     ke ❓ padahal AI sendiri berkali-kali menulis "Di Surabaya ada
     apartemen…". Kini kota dibaca balik dari pesan AI — aman, karena AI
     tidak pernah menyebut kota yang belum ditetapkan.

  6. Q9 — PENOLAKAN TELANJANG = MANDIRI (M67)
     Q9 berbentuk PILIHAN ("langsung jadwalkan ATAU perlu koordinasi dulu?").
     "Tdk perlu", "Tdk mau", "gak usah", "saya survei sndri" memilih cabang
     pertama = tidak perlu koordinasi = Mandiri. Dulu semuanya null →
     pertanyaan yang sama diulang 4× sampai customer terpaksa mengetik
     kalimat panjang. Nilai Q9 untuk keputusan sendiri kini SELALU persis
     "Mandiri" (dulu kode menghasilkan "Sendirian", melanggar aturannya sendiri).

  7. Q11 — SATU KATA TIER SUDAH CUKUP (M68)
     "Yang semi, Kak" / "semi, Kak" / "Semi" gagal karena Phase 1 mewajibkan
     kata "furn" muncul bersama "semi" → pertanyaan diulang 3×. Kini deteksi
     berpasangan: bila AI baru menanyakan furnitur, satu kata tier cukup.

  8. Q_FAC — FASILITAS AKHIRNYA MASUK ANTREAN (M69)
     Fasilitas TIDAK PERNAH ditanya: `findNextQuestion()` sama sekali tidak
     punya Q_FAC. Summary keluar tanpa data fasilitas. Kini Q_FAC wajib,
     ditempatkan SETELAH Q14 (menempatkannya sebelum Q14 memotong alur BELI
     — ketahuan lewat A/B test, 4 tes gagal). Jawaban "standar/terserah/
     semua" → isi fasilitas standar per tipe, JANGAN ditanya ulang.

  9. Q9b/Q9c — JADWAL SURVEI: TANGGAL DULU, BARU JAM (M70)
     Juga sama sekali tidak ada di antrean. Kini dua pertanyaan terpisah.
     Customer BERHAK menolak survei — "lihat listing saja"/"skip"/"belum mau
     survei" dicatat "Minta listing" dan jam TIDAK ditanya lagi. Tanggal
     disimpan dalam format rapi ("20 Agustus 2026"), bukan ISO string.

  10. HINDARI/PREFER — PENGHINDARAN BERBASIS JARAK (M71)
      "Saya mau tempat yang jauh dari pemakaman, masjid, gereja, diskotik"
      menghasilkan `UNKNOWN` (tak satu pun kata kunci cocok) → LLM mengarang
      "bau busuk"/"tidak ramai" dan menaruh "jauh dari masjid" di PREFER
      (arah terbalik). Kini ada ekstraktor `FAR_RE`; "jauh dari X" SELALU
      Hindari, tidak pernah Prefer. Baris Hindari juga kini memuat bentuk
      NEGATIF ("Tempat panas"), Prefer memuat bentuk POSITIF ("Tempat yang
      sejuk") — dulu keduanya digabung jadi "Tempat yang sejuk : Hindari
      tempat yang panas" yang terbaca terbalik.

  11. KOTA vs AREA — PERTANYAAN GABUNGAN MERACUNI SLOT (M60/M61, dari V5,
      tetap berlaku) Q2 kini KOTA saja; area/kecamatan baris terpisah.
      Label summary "Kota" (bukan "Lokasi") + baris "Area".

  12. SINGKATAN BARU: sndri/sndrian→sendiri/sendirian, srvei→survei,
      jln→jalan, msk→masuk, sya→saya, ak/aq→aku. ⚠️ "jl" SENGAJA TIDAK
      ditambahkan — itu prefiks nama jalan ("Jl. Darmo") yang harus utuh.


================================================================================
  1. OVERVIEW
================================================================================

Elevan Property = platform manajemen properti berbasis web + AI chatbot WhatsApp
multi-agent untuk pasar Indonesia. Menghubungkan agen properti dengan calon
pembeli/penyewa lewat WhatsApp, memakai AI untuk mengkualifikasi kebutuhan
customer secara otomatis (Q1–Q14), lalu menghasilkan brief/rekomendasi.

Konsep inti:
  - Website + floating chatbot pencarian properti (publik, tanpa login)
  - WhatsApp chatbot multi-agent: tiap agent punya nomor/device sendiri
  - AI 5-opsi: satu PRIMARY (via env, saat ini `chatgpt`) → Private Agent
    (deterministik, selalu ada sebagai fallback)
  - Qualification flow Q1–Q14 SELALU jalan; RESPOND_CATALOG_RUN hanya
    mengontrol apakah katalog ditampilkan SETELAH summary
  - Data properti: DB (per-agent) + JSON fallback + Rumah123 live (opsional)
  - Landmark: peta kurasi 45 kota + Google Places live (dorman, billing off)
  - Admin dashboard: CRUD Country/Province/City/Location/Facility/Property/
    Customer (7 modul)

Pengguna:
  - AGENT   : kelola katalog & percakapan sendiri; bisa takeover AI per-customer
  - CUSTOMER: chat via WhatsApp, dikualifikasi AI, terdaftar otomatis
  - ADMIN   : master data & monitoring

Deployment:
  - Frontend : https://propmatches.netlify.app (Netlify)
  - Backend  : Node.js port 5055 (ngrok auto-start untuk dev webhook)
  - Database : MySQL `db_property` (Sequelize ORM v6)

  4. PENGEMBANGAN — DEVELOPMENT GUIDE

SETUP LOKAL
  Backend  : cd backend && npm install && npm run dev      (port 5055)
  Frontend : cd frontend && npm install && npm run dev     (port 5173)
  Build FE : cd frontend && npm run build                  (→ dist/)

  cd backend && node scripts/sync-db.js
  ⚠️ ensureRequiredDatabaseColumns() HARUS jalan SEBELUM sequelize.sync().

MENAMBAH / MENGUBAH PERTANYAAN KUALIFIKASI (pola wajib)
  1. Tambah field di state (aiPromptBuilderService.js, blok inisialisasi)
  2. Tambah EKSTRAKTOR:
       - Phase 1 bila jawabannya berdiri sendiri (tak butuh konteks AI)
       - Phase 2 (loop pasangan) bila butuh tahu AI baru bertanya apa
  3. Tambah pertanyaan di findNextQuestion() pada POSISI yang benar
     ⚠️ Menyisipkan sebelum Q14 memotong alur BELI — taruh sebelum
        `return null` bila pertanyaan berlaku untuk semua tipe (M69)
  4. Tambah baris ke buildQualificationStateBlock()
  5. Tambah baris ke template summary (prompt + doc 04)
  6. Update skill docs KETIGA folder (byte-identical untuk 2 folder runtime)
  7. Tulis tes regresi dengan TRANSKRIP NYATA, termasuk kontrol NEGATIF
  8. Jalankan SELURUH suite — bandingkan dengan baseline, bukan hanya file baru

ATURAN SYNC SKILL DOCS (WAJIB)
  skills/claude_responds/docs/*.md ≡ skills/chat_gpt_responds/docs/*.md
  (byte-identical, 13 file per sisi). skills/elevan-property-assistant/ adalah
  edisi STANDALONE — sudah menyimpang, TIDAK di-load kode, tapi tetap perlu
  diperbarui karena di-upload manual ke OpenAI platform skills.

DISIPLIN TOKEN (WAJIB — lihat §5 M62)
  Ukur dampak setiap penambahan ke prompt. Pola aman: emit STRING KOSONG saat
  data tak tersedia (0 token tambahan). Bila sebuah loop bertahan meski
  DIREKTIF FINAL benar → tambahkan EKSTRAKTOR, bukan aturan prompt.

KONVENSI KODE
